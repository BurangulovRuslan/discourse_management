# Атлас дискурса Андрея Курпатова

Атлас помогает исследовать, как в книгах Андрея Курпатова связаны представления о мышлении, человеке и действии. Корпус объединяет **50 книг, 4698 узлов, 11441 связь и 5370 уникальных размеченных цитатных фрагментов**.

Основной вход — **Explorer** в `site/index.html`: интерфейс на Angular с большой единой картой **всех 4698 узлов и 11441 реальной связи**. Визуальный язык сочетает тёмный фон, медные линии, кремовую типографику и журнальную подачу материалов. **Legacy** в `site/legacy.html` сохраняет полный прежний исследовательский атлас и его инструменты. Между версиями можно переключаться: ссылка на Legacy находится в Explorer, обратная ссылка — вверху Legacy. Старый адрес `atlas.html` открывает Legacy с сохранением параметров ссылки.

## Как пользоваться Explorer

1. **Исследуйте карту.** Перетаскивайте её, приближайте колёсиком или кнопками масштаба. Карта поддерживает жесты на сенсорном экране. С клавиатуры: стрелки перемещают карту, `+` и `−` меняют масштаб, `0` показывает её целиком.
2. **Откройте материал.** Наведение на узел показывает его название и число связей. Нажатие открывает полноценное журнальное досье: исходное описание без сокращения, тематические разделы, оговорки, цитаты и соседние материалы. Каждая цитата ведёт на страницу источника с адресом конкретного фрагмента.
3. **Найдите вопрос.** Поиск или `Ctrl+K` / `⌘+K` помогает найти узел и цитату среди всех 5370 цитатных фрагментов. Введите от двух символов: например, «мышление» или фрагмент цитаты. Поиск не различает регистр и «е/ё»; для более широкого результата используйте короткую основу слова. Полный индекс цитат подгружается при обращении к поиску или открытии материала.
4. **Продолжите по связи.** Переход к соседнему материалу показывает реальное отношение из аналитической разметки. Сохраняйте интересующие узлы, чтобы вернуться к ним; коллекция хранится в этом браузере на этом устройстве.

Карта использует **единую плоскость без отдельных слоёв по типам узлов**. Координаты заранее рассчитаны алгоритмом ForceAtlas2 по полному реальному графу: все узлы и связи участвуют в расчёте и отрисовке. При изменении масштаба меняется подробность подписей; узлы и рёбра не отсекаются. Положение и длина линии помогают ориентироваться и не являются самостоятельной мерой смысловой близости, хронологии или силы доказательств.

## Когда открыть Legacy

Legacy содержит сравнение двух книг с отдельными цитатами каждой, цепочки аргументации, эволюцию понятий, развитие по годам, реестр исследований, авторов и работ, подробное кодирование и полный граф без ограничения числа узлов.

На карте сплошные связи обозначают описания или отсылки в тексте, пунктирные — аналитическую реконструкцию. Направление связи и её точная формулировка доступны в материалах и Legacy. Наличие связи само по себе не доказывает причинность. Ограничения интерпретации, различия авторских голосов и оговорки исследований сохранены в досье.

## Данные и источники

Единый аналитический снимок — `site/atlas-data.json`. Данные для Explorer генерируются из него без изменения названий узлов и текста цитат:

- `site/explorer-data.json` — все книги, узлы и связи, координаты реальной карты, степени узлов, краткие описания и выборка цитат для быстрого первого открытия; размер менее 3.5 MB.
- `site/explorer-dossiers.json` — полные описания и содержательные разделы всех 4698 узлов, исходные семантические поля без повторения цитат и формулировки всех 11441 связей; загружается по запросу.
- `site/explorer-search.json` — полный индекс всех 5370 цитатных фрагментов с адресами источников, авторством и связанными узлами; загружается по запросу.
- `site/sources/` — страницы размеченных цитатных опор с якорями страниц и абзацев. Они содержат использованные фрагменты; полные книги в публичный пакет не включены. Для OCR-источников возможны ошибки распознавания, а адрес PDF относится к физической странице локального издания.
- `site/kurpatov.graphml`, `site/research-register.csv`, `site/analytical-report.html` — полный граф, табличный реестр и отчёт для чтения.

На карте используется короткое представление материала; при открытии досье загружается полный исходный контекст. Счётчики отражают разметку корпуса, а не частоту слов, силу доказательств или число независимых исследований. Переиздания могут повторять один материал.

## Локальная сборка и просмотр

Нужны **Python 3.10+**, **Node.js ветки 22 версии 22.14 или новее** и npm. Фронтенд использует **Angular 20.3**, standalone-компоненты и zoneless change detection. Отдельный сервер приложений или база данных для опубликованного сайта не требуются.

Из корня репозитория выполните по порядку:

```sh
python scripts/build_site.py
cd frontend
npm ci
npm run build
cd ..
python scripts/build_site.py --manifest
python scripts/check_site.py
python -m http.server 8000 --directory site
```

Откройте [Explorer на localhost:8000](http://localhost:8000/) или [Legacy](http://localhost:8000/legacy.html). На системах, где Python вызывается как `python3`, замените `python` в командах. Просматривайте Explorer через HTTP: он загружает JSON из каталога сайта.

Первая команда создаёт Legacy, страницы источников и экспорты. `npm run build` рассчитывает координаты полного графа, собирает Angular и публикует новый `site/index.html` и файлы в `site/assets/explorer/`. Расчёт использует закреплённые версии Graphology и ForceAtlas2, детерминированные начальные координаты и все исходные связи. При неизменной топологии готовая раскладка используется повторно; `npm run layout -- --force` пересчитывает её. Затем обновляется манифест и выполняется проверка ссылок, якорей, полной топологии, координат каждого узла, семантической полноты досье, исходных цитат и отсутствия приватных путей и полных книг. Результат записывается в `validation.json`.

Для разработки с автоматическим обновлением интерфейса:

```sh
python scripts/build_site.py
cd frontend
npm ci
npm start
```

Откройте [localhost:4200](http://localhost:4200/). Сначала генерируются данные и Legacy, затем Angular dev server обслуживает их вместе с интерфейсом. Команда `npm start` предназначена для разработки; готовый публикуемый сайт создаётся командой `npm run build`.

GitHub Actions собирает и проверяет сайт для pull request в `main`. После изменений в `main` он также публикует каталог `site/` через GitHub Pages. Workflow можно запустить вручную; публикация разрешена только для ветки `main`.
